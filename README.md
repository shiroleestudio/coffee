# MY COFFEE RECIPE

직접 모은 커피 레시피 아카이브, **브루잉 타이머**, **추출 기록**. 폰을 한 손에 들고
추출하면서 쓰는 걸 전제로 만들었습니다.

- **레시피** — 17개 기본 레시피 + 직접 추가.
- **타이머** — 타임라인을 재생하며 지금 저울에 찍혀야 할 g 과 **붓는 방식**을 알려줍니다.
  나선·원·센터 푸어 같은 궤적, 물줄기 굵기, 붓는 속도를 짧은 애니메이션으로 보여줍니다.
  레시피를 열면 단계마다 바로 움직이고, 뜸 동안에는 다음 푸어를 미리 재생합니다.
- **기록** — 내린 뒤 맛을 고르면 다음에 바꿀 것 한 가지를 알려줍니다. 레시피별로 쌓여
  "가장 잘 나온 설정" 을 다시 꺼내 쓸 수 있습니다.
- **원두** — 로스팅 날짜로 디게싱 일수를 세고 기록에 묶습니다.
- **그라인더 환산** — 레시피의 코만단테·EK43·타임모어 값을 내 그라인더(기본 Femobook A2) 값으로
  바꿔 보여줍니다. 원본에 두 그라인더 값이 있으면 각각 환산하고, 서로 어긋나면 알려줍니다.
- **시로 테마** — 빅 히스토리 연표와 같은 결의 아기 토끼 시로. 연한 종이(라이트, 기본)와 밤(다크),
  설정에서 라이트/다크/시스템을 고릅니다. 토끼 귀 표식·당근(즐겨찾기)·발자국(타이머)·커피 내리는 시로가
  화면 곳곳에 있습니다. 손글씨 제목은 Gaegu(SIL OFL)를 고정 문구만큼만 추려 내장했습니다.

## 실행

```bash
npm install
npm run dev          # 개발 서버
npm run build        # dist/ 로 빌드
npm run build:single # dist-single/index.html — 외부 의존성 없는 단일 HTML 파일 하나
```

`build:single` 로 나온 `dist-single/index.html` 은 파일 하나로 완결됩니다. 폰에 복사해서
바로 열거나, 아무 정적 호스팅에나 올리면 됩니다. 네트워크 없이도 동작합니다.

## GitHub Pages 배포

주소: **https://shiroleestudio.github.io/coffee/** (저장소 shiroleestudio/coffee)

`main` 에 푸시하면 `.github/workflows/deploy.yml` 이 검사(lint·테스트) → 빌드 → 배포합니다.
검사가 실패하면 배포하지 않으므로, 잘못된 빌드가 돌고 있는 사이트를 덮어쓰지 않습니다.

Pages 설정은 Settings → Pages → Build and deployment → Source = **GitHub Actions** 입니다(이미 되어 있음).

배포본은 단일 HTML 파일과 달리:

- **홈 화면에 추가**하면 앱처럼 열립니다 (아이콘, 전체 화면).
- **서비스 워커**가 파일을 저장해 두어 오프라인에서도 열립니다. 온라인이면 새 배포본을 받아옵니다.

알아둘 것:

- **기록은 기기마다, 주소마다 따로입니다.** 기록·원두·즐겨찾기는 서버가 아니라 그 브라우저에
  저장됩니다. 파일로 열던 버전과 Pages 버전은 서로 다른 저장소를 씁니다 — 옮기려면
  설정 → 백업에서 내보내고 불러오세요. 기록은 공개되지 않습니다.
- **공개 사이트입니다.** 주소를 아는 사람은 누구나 레시피를 볼 수 있습니다 (저장소도 공개).
- 같은 조직의 다른 Pages 프로젝트와 브라우저 저장소를 공유합니다(`shiroleestudio.github.io`).
  이 앱의 키는 `mcr:` 로 시작해 겹치지 않지만, 다른 앱이 저장소 전체를 지우면 같이 지워집니다.
  가끔 백업을 내보내 두세요.

## 그라인더 환산에 대해

레시피는 대부분 코만단테 C40 클릭 수로 적혀 있습니다. 설정에서 내 그라인더를 고르면
그 그라인더의 클릭 수로 환산해 보여주고, 원본 값도 작게 함께 남깁니다.

환산은 두 가지를 씁니다.

1. **클릭당 버 이동 거리의 비** — 코만단테 약 30µm, Femobook A2 약 18µm 이므로
   코만단테 1클릭은 Femobook 약 1.67클릭입니다.
2. **기준점** — 각 그라인더에서 V60 이 잘 나오는 클릭 수(코만단테 22, Femobook A2 45).
   0점 위치가 달라 비례만으로는 맞지 않기 때문에 이 점을 지나도록 맞춥니다.
   Femobook A2 는 공개 리뷰 권장값이 50 이지만, 실제로 V60 에 원두따라 40~50 을 쓰고 있어서
   그 중간인 45 를 기본값으로 두었습니다.

**이 값은 정답이 아니라 출발점입니다.** 버 모양과 0점 설정이 다르면 같은 간격이라도
입자 분포가 달라집니다. 그래서 설정에 **환산 기준 보정**을 뒀습니다 — 내 그라인더로
V60 을 내려 가장 잘 나온 클릭 수를 넣으면 모든 레시피의 환산값이 그만큼 함께 움직입니다.
한 번 보정해 두면 그 뒤로는 내 그라인더에 맞는 값이 나옵니다.

**원두마다 분쇄도가 다르면** 원두 탭에서 원두별로 "V60 기준 클릭" 을 넣으세요. 레시피 화면의
"지금 쓰는 원두" 에서 그 원두를 고르면 모든 레시피가 그 원두의 기준으로 다시 환산됩니다.
우선순위는 **원두별 기준 > 설정의 보정값 > 그라인더 기본값** 입니다. 원두 카드에는 그 원두로
마지막에 기록한 분쇄도가 같이 보여서 기준을 정할 때 참고할 수 있습니다.

### EK43

EK43 은 다이얼이 두 종류이고 같은 숫자가 전혀 다른 굵기입니다. [Honest Coffee Guide](https://honestcoffeeguide.com/mahlkonig-ek43-0-16-grind-settings/)
기준으로 둘 다 입자 180~803µm 를 덮으므로 **0~16 다이얼은 숫자 하나 ≈ 39µm, 1~11 다이얼은 ≈ 62µm** 입니다.
기준점은 같은 자료의 척도에서 코만단테 22클릭(약 700µm)과 같은 자리 — 0~16 은 13.5, 1~11 은 9.4.

레시피의 EK43 값을 확인한 결과:

| 레시피 | 원본 | Femobook A2 환산 | 코만단테 기준 환산 |
|---|---|---|---|
| 하리오 V60 깔끔 (Hot) | EK43 13~14 | 44~46 | 51.5~53.5 |
| 하리오 V60 깔끔 (Ice) | EK43 12.5~13 | 43~44 | 48.5~50 |
| 용챔 약배전 (Hot) | EK43 **9.0** | 43.5 | 51.5~55 |

- 용챔의 **9.0 은 1~11 다이얼 값으로 봤습니다.** 0~16 다이얼의 9 는 약 530µm 로 옆의 코만단테 26~28
  (굵은 쪽)과 전혀 맞지 않지만, 1~11 다이얼의 9 는 약 680µm 로 다른 EK43 레시피와도 들어맞습니다. 추론입니다.
- 세 레시피 모두 **EK43 쪽 환산이 코만단테 쪽보다 6~10클릭 가늘게** 나옵니다. 원본 작성자의 그라인더 보정이
  공개 자료의 척도와 다르다는 뜻입니다. 앱은 두 값을 모두 보여주고 차이를 알립니다.

새 그라인더는 `src/lib/grinders.ts` 의 `GRINDERS` 에 추가하면 됩니다.

## 레시피 추가하기

두 가지 방법이 있습니다.

**앱 안에서** — 우하단 `레시피 추가` 버튼. 단계마다 붓는 방법(궤적·물줄기·속도·교반)도 고를 수 있고, 종료 시각을
적으면 타이머가 거기까지 돕니다. 브라우저에 저장되고, 설정에서 JSON 으로
내보낼 수 있습니다. 모카포트·에스프레소·캡슐 탭은 아직 비어 있는데, 여기에 쌓으면 됩니다.

**저장소에 심어서** — `src/data/recipes.ts` 에 항목을 추가하면 모든 기기에서 기본으로 보입니다.
앱에서 내보낸 JSON 을 그대로 옮겨 붙여도 됩니다. 추가한 뒤 `npm test` 로 수치를 확인하세요.

```ts
{
  id: 'bialetti-basic',
  title: '비알레티 기본',
  category: 'mokapot',
  serve: 'hot',
  roast: 'dark',
  beanG: 16,
  waterG: 120,     // steps 의 waterG 합과 같아야 한다
  tempC: 95,
  grind: '곱게',
  gear: '비알레티 모카 익스프레스 3컵',
  totalSec: 240,
  steps: [
    { atSec: 0, waterG: 120, label: '보일러에 뜨거운 물 채우기' },
    { atSec: 60, waterG: 0, label: '중불로 가열' },
  ],
}
```

`atSec` 을 `null` 로 두면 시계에 매이지 않는 단계가 되고, 그런 단계가 하나라도 있으면
타이머는 자동 진행 대신 수동 진행 모드로 바뀝니다. `waterG` 가 `null` 이면 "눈대중"으로 표시됩니다.

## v1 에서 달라진 것

이전 버전은 단일 HTML 파일에 브라우저 Babel 로 JSX 를 컴파일해 쓰던 앱이었습니다.
옮기면서 바꾼 것들:

- **수치를 문자열에서 숫자로.** `"18g"`, `"92℃"`, `"2:40"` 이라 산술이 불가능했습니다.
  숫자가 되면서 비율 표시, 원두량 환산, 누적 투입량 계산이 가능해졌습니다.
- **타이머.** 모든 레시피가 `timeline` 을 갖고 있었지만 표로만 보여줬습니다. 이제 재생됩니다.
- **중복 필드 정리.** `waterAmount` 와 `totalWater` 가 같은 사실을 두 번 적고 있었고
  용챔 약배전 Hot 에서 서로 어긋났습니다(240g vs 230~240g). 실제 단계 합인 230g 으로 통일했습니다.
- **`estTime` 부활.** 정의만 있고 화면에 안 쓰이던 필드였습니다.
- **누적/증분 표기 통일.** 레시피마다 "1차 60g" 과 "1차 115g까지" 가 섞여 있었습니다.
- **접근성.** 카드가 `div onClick` 이라 키보드로 열 수 없었고, 모달은 Esc 로 닫히지 않고
  포커스가 갇히지도 풀리지도 않았습니다.
- **기록이 남습니다.** v1 은 레시피를 보여주기만 하고 내가 뭘 내렸는지는 몰랐습니다.
  기존 브루잉 앱들(Filtru, Coffee Book, Beanconqueror 등)이 공통으로 가진 축입니다.
- **런타임 Babel 제거.** CDN 에서 2MB 넘는 컴파일러를 매번 받아 브라우저에서 JSX 를
  컴파일했습니다. 지금은 빌드 시점에 끝내고 단일 파일 기준 240KB 입니다.

## 운영

- **작업 규칙**은 `AGENTS.md`(사람과 AI 공용). `CLAUDE.md` 는 그 파일을 가리키기만 합니다.
- **배포 확인**: `main` 푸시 → Actions 탭 "Deploy to GitHub Pages" 가 초록이면 1~2분 뒤 반영. 검사가 빨갛면 사이트는 바뀌지 않습니다.
- **되돌리기**: `git revert <커밋>` 후 `main` 푸시. 워크플로가 다시 배포합니다.
- **빌드 도구가 썩었을 때**: 이 앱은 Vite·React·Tailwind 에 묶여 있어 몇 년 뒤 `npm ci` 가 안 될 수 있습니다. 보험이 둘 있습니다.
  (1) 릴리스마다 `npm run build:single` 의 `dist-single/index.html` 을 GitHub Releases 에 첨부해 둡니다 — 이 파일 하나는 의존성 없이 영원히 열립니다.
  (2) `legacy/v1-single-file.html` 은 빌드 도구가 없던 첫 버전입니다.
  의존성 업그레이드는 깨졌을 때만, 한 번에 하나씩(`npm test`·`npm run smoke` 로 확인).
- **Node**: `.nvmrc`(22). 매년 10월 LTS 가 바뀌면 `.nvmrc` 와 `.github/workflows/deploy.yml` 의 `node-version` 을 같이 올립니다.
- **사용자 데이터**는 브라우저 안에만 있습니다. 백업은 앱의 설정 → 백업(내보내기·불러오기)으로 사용자가 합니다. 서버도 계정도 없습니다.
- **라이선스**: 코드는 `LICENSE`(MIT). 레시피 데이터(`src/data/recipes.ts`)는 출처가 적힌 공개 레시피를 수치로 옮긴 것입니다.
- **릴리스**: `CHANGELOG.md` 가 아직 없습니다 — 다음 릴리스에 만들고, Releases 에서 `vX.Y.Z` 태그.
- 계정·정기 점검·다른 저장소: 허브 저장소(shiroleestudio.github.io)의 `STUDIO.md`.
